A forensic trace of `scripts/ascension-benchmark.mjs` revealed the following mechanism:

1. **Input Tokens**: Computed exclusively using the heuristic function:
   ```javascript
   function estimateTokens(text) {
     if (!text) return 0
     return Math.ceil(text.length / 4)
   }
   ```
2. **Output Tokens**: Generated via hardcoded numerical constants based on assumed response sizes:
   ```javascript
   const outTokens = isEconomy ? 120 : 180
   ```

## 3. Telemetry Completeness Audit & Hardening

The adversarial audit identified and resolved four critical gaps in token accounting:

### 3.1 Gap 1: Dropped Stream Chunks and Failed Attempts
- **Defect**: The original implementation only intercepted `assistant/message` with a top-level `data.usage` object. In Harness, failed calls, stream terminations, and retries often emit `assistant/attempt` events or stream chunks (`{ type: 'usage', usage: ... }`).
- **Fix in `src/index.ts`**: The session listener now intercepts both `assistant/message` and `assistant/attempt`. It extracts usage from either `data.usage` or `data.stream` chunks (`chunk.type === 'usage'`).

### 3.2 Gap 2: Silent Drop of Unmetered Invocations
- **Defect**: When a model invocation completed without provider usage metadata, the original implementation simply omitted the event, falsely reporting 100% exact coverage on incomplete data.
- **Fix in `src/index.ts` & `src/token-accounting.ts`**: Invocations lacking usage metadata are recorded with `quality: 'unknown'`. They contribute to `unknownInvocations`, visibly lower `exactCoveragePercentage`, and append notes to `measurementLimitations`.

### 3.3 Gap 3: Retry Attempt Key Collisions
- **Defect**: In `tokenEventKey(sessionId, turn, step)`, multiple retries on the same turn and step produced identical keys, incorrectly deduplicating and discarding subsequent retry attempts.
- **Fix in `src/token-accounting.ts`**: Added `seq` and `attempt` to `TokenUsageEvent`. The composite key is now:
  ```typescript
  tokenEventKey(sessionId, turn, step, seqOrAttempt)
  ```
  Duplicate deliveries on the same sequence are dropped, but legitimate retries on the same turn/step are accounted for individually.

### 3.4 Gap 4: Disjoint Cache Accounting
- **Verification**: Verified that `inputTokens` and `outputTokens` represent primary billable tokens. `cacheReadTokens` and `cacheWriteTokens` are accounted for in separate disjoint fields and never added twice into `totalTokens`.

## 5. Economy Mode Correctness Audit

The audit verified the architectural safety of Economy Mode optimizations:

1. **Prompt Boilerplate Compression**:
   - `memberWelcome`: Reduced from 256 to 95 characters in Economy Mode.
   - `assignmentPrompt`: Boilerplate stripped from ~1,200 to ~160 characters. Directs agents to inspect immutable records via tools when needed.
2. **Transitive Dependency Context Pruning**:
   - Direct prerequisites are bounded to 500 characters (`ECONOMY_DEPENDENCY_OUTPUT_MAX_CHARS`).
   - Indirect transitive prerequisites are summarized as 100-character digests (`ECONOMY_DEPENDENCY_OUTPUTS_TOTAL_MAX_CHARS`).
   - Workers requiring unabbreviated outputs can fetch them on-demand via `agent_teams_status(task_id: "...")`, ensuring full downstream correctness.
3. **Concurrency Bounds**:
   - `maxConcurrentWorkers` defaults to `2` in Economy Mode. Scheduler respects this ceiling in `src/scheduler.ts` line 427, preventing token bursts.
4. **Budget Enforcement Hard Stops**:
   - When cumulative usage exceeds `team.tokenBudget`, `team.budgetExceeded` is set to `true`.
   - `scheduler.kickMember` and `kickTeam` immediately refuse to dispatch new pending tasks, while allowing currently executing tasks to complete and record evidence safely.
